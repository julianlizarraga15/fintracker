## Safe web deployment workflow

The old web workflow was unsafe: it used the standard Compose file, implicitly loaded `.env`, and ran `down --remove-orphans`. The replacement was reviewed and merged in [PR 22](https://github.com/julianlizarraga15/fintracker/pull/22), enabled, and used successfully for production run [40164105266](https://github.com/julianlizarraga15/fintracker/actions/runs/40164105266). It builds only changed services with run-specific tags, gates deployment on the shared backend/package/browser tests, uses the isolated Compose file and `/dev/null` as Compose's interpolation env file, and updates only the selected backend or frontend. Backend updates stop and later restore the valuation timer, drain the current job, acquire the app's shared valuation lock, check health, and retain the previous image for rollback. SSM output handling records status only.

The user later authorized the safe replacement, overriding the earlier request to keep web CI/CD disabled. GitHub reported the workflow active after the successful production run. The first scheduled timer-triggered valuation after this deployment remained pending at the 2026-10-25 05:07 UTC check. Local syntax, YAML, mocked deploy/rollback, SSM payload/polling, production-host Compose parsing, runtime configuration, public health, and authenticated Refresh were checked.

## Guardrails and rollback

Keep the isolated web CI/CD workflow enabled. For a worker rollback, deploy a reviewed CloudFormation change set using a verified safe reader version/image. The web uses unqualified function ARNs, so publishing alone does not route traffic. Keep the credential-free web configuration and least-privilege IAM in place; do not restore broker credentials to EC2. If a reader fails, preserve the last complete snapshot, pause only affected valuations if needed, and restore a safe reader release. Manual backend recreation must use the explicit isolated Compose file and clean bootstrap described in the runbook; do not use default Compose discovery, `down`, or orphan removal.

No further isolation work is blocked on AWS login. Rotation is a separate credential-owner decision; no rotation was required to complete this boundary.
